# Changelog

## 0.3.0 - unreleased
- Settings > Connection has an Import Connections… button, the same import as File > Import Connections.

## 0.2.2 - 2026-11-08

- IT rollout, two files. A `settings.json` in the machine-wide folder (Windows `%ProgramData%\tn5250-terminal`, Linux `/etc/tn5250-terminal`, macOS `/Library/Application Support/tn5250-terminal`, or the path in `TN5250_MANAGED_SETTINGS`) is read at every start and layered under each user's own settings: its defaults are the base the user's defaults override, its sessions show read-only under "Company connections" (right-click: connect, or copy one to your own list), its macros run but cannot be changed, and `"checkForUpdates": false` turns the startup update check off for everyone. A `settings.default.json` next to the executable seeds a user who has no settings yet. Help > Settings File Location lists all three. See DEPLOYMENT.md.
- Macros can be exported to and imported from a `.json` file (Actions > Macros…), the same format the VS Code extension reads and writes.
- Fixed: settings, sessions or macros saved in one window of the app did not show in the other open windows until they were reopened; every window now reloads when another saves.
- Fixed: characters typed with AltGr (@, the euro sign, [ ] { } on German and other layouts) were dropped: Windows reports AltGr as Ctrl+Alt and the terminal treated the chord as a shortcut. They are typed now; Ctrl+Alt chords with a letter or digit stay shortcuts.
- Macros (Actions menu and two toolbar buttons): record what you type and press in a session, or build and tidy one in a full-screen editor modelled on Logitech G HUB: one chip per step on a timeline (red keycaps, typed text, a delay as an underlined number, a wait for the host, a wait for a text on the screen, a prompt), click a chip to change it in place, drag it anywhere, Delete removes it, the + tile (or a right-click on a chip) adds a step or records more after the selected chip. Delays are never recorded (the host sets the pace); a delay is a step you add where a screen needs one. A recording reminds you every 5 minutes that it is still on and ends by itself after 5 minutes without a keystroke. Give the macro a name and a key (a function key or a chord with Ctrl, Alt or Win) and it runs in the active session when that key is pressed. The recorder puts a wait for input after every key the host answers, so a macro never types into a locked keyboard; Actions > Stop Macro stops one. Macros are kept in the settings file; passwords belong in a prompt step, never in the macro.
- The editor shows an arrow between steps, the shortcut key has an (i) with the explanation and an ✕ to remove it, chips slide into place while you drag (the others shuffle out of the way) and after Alt+arrows, and a right-click menu is drawn over the neighbouring chips.
- A macro's shortcut key pressed again while it runs stops it, presses Reset and Erase Input (what it typed so far is wiped) and says so.
- The Macros dialog has a play, pencil and trash can on each row (they light up and draw a ring in their colour on hover; the lid of the trash can opens), New / Record / Import / Export as icons under the title and an ESC key in the corner; the macro editor closes with the same ESC key, top right, and its Reset / Save and run / Save are keycaps too (grey, green, blue). The toolbar's record button blinks while recording and the Macros button is a play button.
- Fixed: a macro could type its text before its keys had moved the cursor (TAB TAB "40" reached the session as "40" TAB TAB: every key went to the session window as its own call, and those calls are not ordered). A window now sends its keystrokes in order, one message per tick.
- Linux: the nfpm packaging (`wails3 task linux:generate:deb|rpm|aur`) names a post-install script that did not exist; it is there now and refreshes the desktop database and icon cache.
- The euro code pages 1140-1149 announce the euro keyboard types CRTDEVDSP lists for them (USE, AGE, DME, FNE, ITE, SPE, UKE, FAE, ICE) instead of the plain ones; 1148 keeps INB.
- File > Import Connections: reads ACS 5250 display session profiles (`.hod`) from `Documents\\IBM\\iAccessClient\\Emulator` or any `.hod` files you pick and adds the ones you select (connection, screen size, code page, workstation name, user profile, display, paste, hotspot, mouse wheel, sound and keyboard options, field colours); a connection already saved is updated from the profile or left alone, your choice, and Undo is offered after the import; passwords are never read. The readers are shared with the VS Code extension, where Juan Concepcion contributed them (tn5250-terminal #7).

## 0.2.1 - 2026-11-08

- Fixed: Actions > Print (host) left the session in X SYSTEM. The host answers the Print key with Read Screen (to Print), X'66', which was not recognised; it now gets the screen image like Read Screen, and the host spools it.

- Fixed: bytes the host sends that are not printable characters (X'01'-X'1F', X'FF': control bytes in file data from bad character conversions) showed as blanks; they now show as a box, as on ACS. Copy and Print Screen show the box too.
- Fixed: a session tab moved to another window said "Not connected" while the session was running, until the connection state changed (reported by thomprl). The connection state is sent again whenever a terminal view loads.

- Bypass sign-on guards QMAXSIGN: sessions for the same user profile and host sign on one at a time, and after the host refuses one the others do not send the password at all (a log line and one dialog say so). Saving the settings, setting the password or reconnecting by hand tries again. Five tabs reloaded with a wrong code page, or a stale saved password on an auto-reconnect loop, no longer disable the profile. The session log names the code page in use on every connect.

- Windows: sessions can be spread over several windows, as in ACS. Drag a tab out of the window to detach it into a window of its own, drag it onto another window of the app to merge it there, drag within the bar to reorder (Window menu: New Window, Move Tab to New Window, Merge Tab into Main Window). The session keeps running throughout: every session lives in one hidden page of the app, the windows only show them. Closing a window hands its sessions to the main window.
- Connections panel: each saved session shows its open tabs underneath (in any window) with their state; click one to bring it to the front. Tabs of quick connects sit under "Other connections".
- Status bar: click it (or View > Session Log) and the session log grows up out of it; the arrow or Esc minimises it. Notifications go to the log too.
- View > Appearance: System, Light or Dark for the whole app; the window background follows the system scheme while the page loads.

- Fixed: Save Screen left the GUI windows out of the image, so a screen restored after a called program (Restore Screen) came back with the window borders as raw blue cells instead of windows. The image now carries every Create Window with the cells it shows, in order, and Remove GUI Window still uncovers the screen beneath.
- Ported to Wails v3 (3.1.0): one process can own several windows, which the next entries build on. Same features, same settings file and saved passwords. Build metadata moved from `wails.json` to `build/config.yml`; the Linux build now uses GTK 4 + WebKitGTK 6.0 (Ubuntu 24.04+, Debian 13+). A second launch of the exe (`tn5250-terminal host[:port]`) now opens that session in the running window instead of only raising it.

## 0.2.0 - 2026-11-04

- Fixed: a status bar notice (for example "Opened https://..." after a PC command) never cleared; it now goes away after five seconds and is kept in the session log.
- Fixed: a password with characters that differ between EBCDIC code pages (`!`, `@`, `#`, `[`, `]` ...) failed with CPF1120 when Host Code Page did not match the host's CCSID, and nothing pointed at the cause. After such a failed sign-on the app shows a one-time hint naming the characters and the code page in use (log too, never the password); the Host Code Page and Bypass signon help texts and a new README Troubleshooting section explain it; the keyboard type sent with the workstation name now follows the code page (tn5250-terminal #5).
- Security review (traces, sign-on, TLS): a saved session trace blanks what was typed into non-display fields (passwords), keeping the lengths. Bypass sign-on types the password only into a non-display field, on the first screens after connect, and logs when it skips a screen. Removing a session removes its saved password unless another session still signs on with the same user at the same host. Bypass sign-on over plain telnet warns on the settings page and in the log. Non-display cells leave the engine as blanks, so the page never holds them.
- TLS: the host certificate is checked by the app itself against the system roots plus an optional CA file (`tlsCaFile`, e.g. an IBM i DCM local CA); a refused certificate shows its SHA-256 fingerprint and "Trust this certificate" pins it for that session (`tlsPinnedCertificate`); TLS 1.2 stays the minimum; switching Protocol to TLS moves port 23 to 992 (and back). The certificate error now offers those before "turn verification off".
- NEW-ENVIRON: KBDTYPE and CHARSET follow the host code page (IBM's keyboard type table and the CDRA character set ids) instead of USB/697 for every code page; a new Keyboard type setting overrides the keyboard for countries that share a code page; unknown code pages send DEVNAME only, as RFC 4777 prescribes.
- Fixed: a Write Structured Field carrying more than one structured field was scanned byte by byte after the first one, so a X'04' inside the second read as a command.
- Settings page: Save and Assign no longer jump to the top (the page updates in place, or restores the scroll position when it must rebuild); confirmations and notices are one corner toast with a queue; field validation stays on the field.
- Fixed: selection field choices were laid out two columns to the right of where the host puts them (the field address is the text's leading attribute; the check box / radio button cells sit to its left), so pull-down text ran past the window and lost its last letters.
- Fixed: a host error message written with Write Error Code stayed on the message line after the host repainted, and the read that follows such a message homed the cursor to the first field; now the row it covered comes back with the next write and the cursor stays where the error happened. A cursor the host places inside a selection field lands on its first choice, so the arrow keys work the field at once. I/O fields (DDS data type I) refuse keyboard data with error 0004.
- Fixed: System Request (Shift+Esc), Attention (Esc) and Test Request were swallowed while the host had the keyboard locked (X SYSTEM), so a running program or a long batch could not be interrupted. They now go to the host at any time, as on a real display.
- Entry field FCWs of the enhanced interface: continued entry fields (DDS CNTFLD) are edited as one field across their segments and go back to the host as one field; word wrap fields (WRDWRAP) keep words whole; cursor progression (FLDCSRPRG) sends Tab to the numbered field and Backtab back; highlighted entry fields (ENTFLDATR) change their attribute while the cursor is in them (shared from tn5250-terminal).
- Selection fields (enhanced 5250 Define Selection Field): menu bars with their separator line, pull-downs, single choice fields and lists (radio buttons), multiple choice fields and lists (check boxes) and push buttons. Tab enters a field at its first choice, the arrows move the selection cursor, Space and / select, Delete deselects, a mnemonic letter or number picks its choice, a click selects, and auto-enter / auto-select / per-choice AIDs send the field at once. The Enhanced style draws radio buttons, check boxes, push button frames, the selection cursor and the mnemonic underline (shared from tn5250-terminal).
- Programmable Mouse Buttons: pointer events the host programmed send the host's AID with the cursor at the pointer, as single events or two-event sequences. Write Data fills an entry field; a window with the restrict-cursor flag keeps Tab, the arrows and clicks inside it (shared from tn5250-terminal).
- Scroll bars (enhanced 5250): a subfile compiled with SFLEND(*SCRBAR), or a selection list, gets the scroll bar the host defines (Define Scroll Bar Field), drawn as a modern bar with arrows and a proportional thumb in the columns the host reserves for it. The arrows scroll one row, a click on the track a page, and the thumb can be dragged; the host receives the Roll key and the scroll increment at the bar's address, as it does from ACS, so the subfile repositions itself. Horizontal bars work the same way with Roll Left / Roll Right (shared from tn5250-terminal).
- Display > Scroll bar on every subfile (off by default): a scroll bar beside every subfile whose last row ends in More..., Bottom or +, even when the display file does not ask for one. It lives in a gutter right of the text and its clicks send Page Up / Page Down; the thumb only shows whether there is more.
- GUI windows carry their title and footer: the Enhanced style draws the window as a frame with a shadow and the title on the top edge instead of the border characters; the Classic style shows the title in the border like a character display.
- PC commands from the host (STRPCCMD / PC Organizer): a host program that runs `STRPCCMD PCCMD('START http://...')` used to leave the terminal on the host's "Required PC program (PCO.EXE) is not active" screen. The terminal now recognises the request, opens http(s) links in the default browser and presses Enter for the host, so the program carries on without a flash of that screen. Other commands ask first (Run / Cancel) and run through the shell (cmd.exe or /bin/sh); PAUSE(*YES) waits for the command to finish. Preferences > Behavior > PC commands from the host: open links (default), always ask, run everything, off (shared from tn5250-terminal).
- The screen no longer resizes itself back and forth when the Connections panel narrows the window by just the wrong amount (Enhanced style, or a zoomed-in screen): the fitted screen never shows scrollbars, and the size is measured so scrollbars cannot change it. A zoomed-in screen scrolls from its top-left corner instead of being cut off on the left (shared from tn5250-terminal).
- Run SQL Scripts and the CL / QSH Console work. The Go host gained a client for the remote command host server (QZRCSRVS, port 8475); SQL runs through RUNSQL, queries are materialised in QTEMP, exported with CPYTOIMPF to a UTF-8 CSV in /tmp and read back over the file server, column types come from QSYS2.SYSCOLUMNS, Qshell output is captured through a stream file. Limits: statements up to 5000 characters, no update counts, NULL comes back empty, 10,000 rows per query kept for paging, Stop takes effect between steps. The message layout of the remote command server was written from the documented client behaviour and tested against a fake server; it still needs a check against a real host.
- IFS browser: a folder tree on the left (lazy, expand with the arrow, click a folder to open it, right-click for Open / Refresh / Copy path, drag the splitter, Folders button hides it), the path as clickable segments (the pencil or Ctrl+L types a path), and drag and drop: drop rows on a folder row, a tree folder or a path segment to move them there (asks first). Dropping files from the desktop still uploads.
- Linux and macOS builds: AppImage, .deb and tar.gz for x86_64 Linux (GTK 3 + WebKitGTK 4.1), a universal .dmg/.zip for macOS 11+ (Intel and Apple silicon, ad-hoc signed). The release workflow builds and smoke-tests every package on its own platform and publishes one SHA256SUMS; CI builds the app on all three.
- Windows: a per-machine MSI (`tn5250-terminal-x64.msi`) for IT deployment next to the per-user setup and the portable zip. Check for Updates recognises an MSI copy and points at the release page instead of trying to update in place.

## 0.1.5 - 2026-11-03

- Keyboard settings page: Assign takes Ctrl combinations and a bare modifier on release (Esc cancels); a key taken from another function says so with Undo; a function whose ACS key is gone is flagged with Restore; Import and Reset at the top with explanations; the .kmp picker opens in Documents\IBM\iAccessClient\Emulator and the import lands in the form until saved (shared from tn5250-terminal).
- A bare Alt press is the terminal's (no menu focus on release); unmapped Ctrl/Alt chords are consumed in the desktop app so the browser engine's own shortcuts never fire; the key overlay names bare modifiers by their key.
- Double-click on a word inside an input field selects the word; a blank inside a field selects the field; a blank elsewhere nothing.
- Save & Reload dialog lists the tabs it reloads; the second button is Apply & Continue; the settings page warns above Save which open tabs a connection change will not reach.
- Colours the Enhanced screen style does not use (Screen background, Active field, OIA background) are greyed out while that style is on, the reason printed beside the row; the Enhanced UI colours while it is Classic. Keyboard page: search, Import and Reset on one line; "No key for ..." warnings can be ignored (keyWarningsIgnored), back when the function gets a key and loses it again or a .kmp is imported.
- Keyboard: the ACS cursor and edit functions that were missing - Fast Cursor Up/Down/Left/Right (3 rows or columns, Ctrl+arrows), Tab Word / Backtab Word (Alt+Right / Alt+Left), Beginning of Field, Delete Word (Ctrl+Delete), Erase Field, Test Request (Ctrl+F12), Rule line on/off (Ctrl+Home). Copy and Paste are keymap actions now, so Dup can be assigned to any key (unassigned by default, as in ACS). The .kmp import knows the standard ACS/HOD function names (shared from tn5250-terminal).
- Settings that only take effect on a new connection are marked on the settings page; saving one while a tab that uses it is open asks Save & Reload (the tab reconnects with the new values) or Save & Close. Before, a screen-size change needed a new tab.

- Saved passwords (Windows Credential Manager) shared by bypass signon, IFS, Run SQL Scripts and the Console; Tools menu entries for Run SQL Scripts and the CL / QSH Console (the host-server clients behind them are not finished yet; the tabs say so).
